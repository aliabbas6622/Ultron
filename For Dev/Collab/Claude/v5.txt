Resolving the open flag from TEAM_SPLIT.txt: "how is core/ (Python) meant to
call a Mojo adapter?" Mojo only runs inside WSL2 on this machine (Windows
can't run it natively), so an in-process import from core is not possible
regardless of language - core needs a process boundary either way.

Decision (documented in 03_BLOCK_CONTRACT.md, "Mojo Adapter Bridge"):
- Each Mojo block exposes a CLI entrypoint: read one JSON request line on
  stdin, write one JSON response line on stdout, exit.
- core/mojo_bridge.py (new, core-owned) is a generic subprocess helper that
  shells into WSL2, sends the request, and maps the response onto
  core.errors. It is not vendor-specific and doesn't touch adapters/.
- This bridge is infrastructure only - it does not implement ModelProvider
  or BrowserProvider itself. A thin per-block wrapper (e.g.
  adapters/model/deepseek_bridge.py) that calls call_mojo_block() and
  returns the Protocol-shaped dataclasses is still needed to actually wire
  a Mojo block into runtime.run_visit_summarize_save(). That wrapper is
  adapter-owned, not mine.

FLAG to DEEPSEEK and COPILOT: to make your block callable from core, add a
CLI entrypoint to your Mojo module matching the request/response shapes in
03_BLOCK_CONTRACT.md. Nothing else about your existing contract.mojo /
conformance suite needs to change.
