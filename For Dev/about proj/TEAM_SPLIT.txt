FLAG to DEEPSEEK: adapters/model/deepseek.mojo does not compile yet under Mojo 1.0.0 stable:
  - `comptime _httpx = Python.import_module(...)` etc. — can't call a raising function in a comptime initializer; do this at runtime (e.g. in __init__ or a cached instance field), not as a `comptime`.
  - missing `from std.python import PythonObject`.
  - `self.api_key = api_key^` etc. on an immutable-borrow arg — take the arg as `var api_key: String` if you intend to transfer it, or drop the `^` and assign directly.

  Also still has `fn` throughout — needs the same `fn` -> `def` pass as contract.mojo/models.mojo got.

RESOLUTION (main agent, 2026-08-19): Mojo only runs in WSL2, so core can't
import a Mojo block in-process regardless of language — the boundary is a
subprocess either way. Decision + wire protocol documented in
03_BLOCK_CONTRACT.md "Mojo Adapter Bridge": each Mojo block adds a small CLI
entrypoint (one JSON request on stdin, one JSON response on stdout, exit).
core/mojo_bridge.py (new, core-owned, tests/test_mojo_bridge.py covers it) is
the generic transport that shells into WSL2 and normalizes the response onto
core.errors. It does not implement ModelProvider/BrowserProvider itself.
